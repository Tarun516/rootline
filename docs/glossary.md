# Glossary

## Analyzer

A versioned component that produces facts, evidence, signals, or inferences from declared inputs.

## Artifact

A physical repository object such as a source file, manifest, configuration, schema, migration, or infrastructure definition.

## Capability

A system-level ability provided by one or more modules, symbols, services, or flows.

## Code Intelligence IR

Rootline's language-neutral representation of program structure and supported relationships. Language adapters translate syntax into this form.

## Deterministic fact

A reproducible analyzer result under declared inputs and coverage. Deterministic does not mean universally complete.

## Evidence

The source locations, resolver trace, structural signals, analyzer identity, revision, or other information explaining why an assertion exists.

## Fact graph

The persisted graph of repository, parser, resolver, configuration, schema, and other deterministic analysis results.

## Flow

An ordered or branching path representing meaningful execution or data movement, such as an HTTP request, event, job, or audio-processing pipeline.

## Inference

A regeneratable interpretation derived from facts and signals, often with semantic-model assistance.

## Learning state

User-specific records describing explored concepts, prerequisites, recommendations, and personal comprehension progress.

## Projection

A bounded view derived from the stored graph for a specific query, abstraction level, flow, subsystem, or viewport.

## Provenance

The lineage of an assertion: repository revision, analyzer/model identity and version, inputs, creation time, and supporting evidence.

## Semantic enrichment

Optional interpretation that adds summaries, labels, subsystem proposals, flow explanations, embeddings, or learning guidance to deterministic facts.

## Semantic zoom

Navigation where zooming changes the abstraction being represented—from system to subsystem, capability, flow, module, file, symbol, and source—not merely visual scale.

## Significance

An explainable assessment of why an entity matters, based on factors such as connectivity, entry-point proximity, flow participation, boundaries, I/O, or state mutation.

## Subsystem

A cohesive, higher-order part of the system that groups related capabilities and implementation.

## User view

User-owned presentation state such as custom groups, annotations, pins, filters, hidden nodes, and layouts. It does not alter facts or inferred system concepts.
